  1. 문제를 구체적으로

    증상과 환경을 적습니다. 무엇이 실패했는지, 어디까지 확인했는지 구분합니다.

  2. 선택의 이유를 함께

    채택한 대안과 다른 대안을 비교합니다. 자원과 운영 비용도 판단에 포함합니다.

  3. 검증한 만큼만

    방법·관측값·조건·한계를 함께 적습니다. 실행하지 않은 검증은 예정으로 남깁니다.

  4. 바뀐 판단을 개정으로

    이전 문장을 최신 근거로 고치고, 변경 이유와 이전 판단을 이력으로 남깁니다.

인프라 / 설계 기록 / 디자인 샘플

페이지는 정적으로, 운영은 가볍게.

문제

읽기 중심의 기술 포털에 별도의 서버 운영이 필요한지 검토한다. 정적 콘텐츠를 제공하는 일과 기존 서비스의 운영을 구분한다.

선택

Astro로 만든 HTML·CSS·이미지를 Cloudflare Workers Static Assets에 배포하는 방식을 선택한다. 기존 서브도메인의 구성이나 인증을 변경하지 않는다.

검증 조건

홈·아티클·정적 자산·없는 URL의 404·이전 버전 복구를 확인해야 한다. 이 글은 디자인 샘플이므로 실제 배포 결과나 지연 수치를 제시하지 않는다.

확인할 범위를 기록하는 예시입니다. 검증 완료나 서비스 성과를 의미하지 않습니다.

문제

선택
