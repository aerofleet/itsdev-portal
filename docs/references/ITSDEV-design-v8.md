## 1. 이번 개정의 방향

**넓은 여백 위에 기록과 도판을 놓고, 읽으면 근거와 개정이 남는 지면.** ITSDEV의 대표 문장인 “만들고, 운영하고, 근거를 남깁니다.”를 홈의 시각 구조와 아티클의 정보 구조에 함께 적용한다.

사용자 피드백은 “너무 각지고 박스 라인들이 너무 많아서 복잡하다”이다. v8은 v7의 읽기 순서·도판·색을 유지하면서 화면을 둘러싸던 프레임을 걷어냈다. 구역은 여백과 글자 크기로 구분하고 이미지만 부드러운 모서리로 묶는다. v7 및 그 이전의 각진 형태·박스·구분선 규칙은 아래 현행 명세로 대체한다.

| 요소 | v8의 결정 | 디자인상 역할 |
|---|---|---|
| 히어로 | 왼쪽 3행 문장 + 오른쪽 2×2 설계 도판 | 한 화면에서 발행자의 태도와 기록의 주제를 읽는다 |
| 모자이크 | 네 개의 둥근 이미지, 프레임 없는 바깥 캡션 | 그림과 제목이 선에 갇히지 않고 이어진다 |
| 대표 기록 | 둥근 남흑색 도판 + 여백으로 구분한 판단 요약 | 하나의 큰 박스로 감싸지 않고 그림과 글을 연결한다 |
| 최근 기록 | 서로 다른 커버 비율, 모바일은 세로 목록 | 데스크톱 리듬과 모바일 제목 가독성을 함께 확보한다 |
| 서비스 | 크기와 시작 높이가 다른 소개 패널 | 실제 운영 서비스와 관련 기록을 구분해 소개한다 |
| 아티클 | 선 없는 문서 정보 + 본문 + 간결한 개정 표 | 정보는 유지하고 표제란의 칸막이는 제거한다 |
| 모션 | 짧은 상승·치수선 그리기, 정지 제어 제공 | 도판이 지면에 놓이는 느낌을 만든다 |

참고 자료의 구성 원리는 발전시키되 이미지·문구·브랜드를 복제하지 않는다. 첨부 memory에 적힌 참고 사이트의 Astro/GSAP/Lenis 사용 여부는 이번 작업에서 확인하지 않았으며 기술 선택의 근거로 쓰지 않는다.

## 2. 적용 범위와 콘텐츠의 진실성

- 적용 대상은 **itsdev.kr 콘텐츠 포털 하나**다. 기존 서브도메인은 이미 운영 중이며 구성·인증·배포·화면 개편을 포함하지 않는다.
- 포털은 Astro 정적 빌드와 Cloudflare Workers Static Assets를 전제로 한다. Astro는 HTML·CSS·자산을 만드는 도구이고 Workers는 그 결과를 제공하는 배포 플랫폼이다.
- OCI 노드·Nginx·Tunnel·loopback 포트는 이 포털 디자인의 전제가 아니다. 서비스 사례의 기술과 포털의 기술을 같은 것으로 표시하지 않는다.
- 동작 시안의 네 글, 문서번호, REV, 날짜, 도판은 **디자인 샘플**이다. 실제 발행·검증·성능 수치·운영 성과를 의미하지 않는다.
- 서비스 개념 도판에는 “실제 화면 캡처 아님”을 표시한다. 화면 이미지가 확보되면 확인된 캡처로 교체하거나 개념 도판을 그대로 유지한다. 임의 대시보드·사용자 수·가동률을 만들지 않는다.
- DJC는 확인된 공개 목적지 `https://djc.itsdev.kr`로 연결한다. WithBuddy는 관련 기록으로 연결하며 제품과 도메인의 관계가 확인되기 전 외부 주소를 추정하지 않는다.
- 실제 연락처·피드가 없는 시안에서 제출·구독 성공을 표시하지 않는다. 공개용 구현에서는 유효한 링크로 교체하거나 해당 동선을 숨긴다.

## 3. 브랜드와 시각 문법

브랜드 ITSDEV, 발행명 Engineering Fieldnotes, 설명 “직접 만든 서비스와 운영의 기록”. 워드마크는 굵은 ITSDEV와 짧은 치수선으로 구성한다. 별도의 캐릭터·3D 심볼은 추가하지 않는다.

표면은 중성 제도지다. **여백을 먼저 사용하고 선은 정보를 전달할 때만 사용한다.** 헤더·섹션·서비스·캡션을 프레임으로 둘러싸지 않는다. 도면의 소재는 이미지와 짧은 워드마크 치수선에 한정한다. 넓은 여백과 굵기 차이로 위계를 만들고 **대표 도판 → 기록 갤러리 → 서비스 사례 → 읽는 원칙**으로 지면의 밀도를 바꾼다.

Cobalt는 이동·선택·포커스, Redline은 개정·정정·검증 미완료 상태를 뜻한다. 상태는 반드시 문자 라벨을 함께 표시한다. 불필요한 대문자 라벨, 순서 없는 장식 번호, 무한 기술 스택 ticker, 배경 패턴, 네온, 커서 추적은 사용하지 않는다. `01~04`는 문제·선택·검증·개정이라는 실제 순서에만 사용한다.

## 4. 디자인 토큰

### 4.1 색과 의미

아래 이름은 동작 시안의 CSS와 일치한다. 별칭을 늘리지 않고 실제 컴포넌트가 사용하는 의미별 토큰으로 관리한다.

| 토큰 | Light | Dark | 용도 |
|---|---|---|---|
| `--paper` | #F6F7F5 | #0F1419 | 페이지 |
| `--surface` | #FFFFFF | #161C23 | 읽기 면·표제란 |
| `--tile` | #E9ECED | #202A34 | 개념 도판 면 |
| `--ink` | #151A21 | #E7EBF0 | 제목·본문 |
| `--muted` | #4F5864 | #AFBAC7 | 보조 설명 |
| `--accent` | #2448B5 | #A4BAFF | 링크·포커스·선택 |
| `--on-accent` | #FFFFFF | #122454 | 강조 버튼의 글자 |
| `--red` | #B3261E | #FF9A8C | 개정·정정·미검증 |
| `--rule` | #D3D8DD | #354352 | 장식 구분선 |
| `--control` | #7A838E | #8B9AAC | 식별이 필요한 경계 |

대표 도판에는 테마와 관계없이 별도 남흑색 면을 사용한다: `--plate #182435`, `--plate-ink #E7EDF5`, `--plate-muted #BAC7D6`, `--plate-accent #9EB7FF`, `--plate-line #46566B`. 마지막 값은 필요할 때 사용할 보조 토큰이며 도판의 외곽 프레임에는 쓰지 않는다. 의미 있는 연결선은 읽을 수 있는 밝은 토큰을 사용한다. 개념 노드는 채운 면과 둥근 모서리로 표현하고 추가 윤곽선을 두르지 않는다.

다크 테마의 강조 버튼은 밝은 Cobalt 바탕 + 짙은 글자 조합이다. 밝아진 `--accent`에 흰 글자를 재사용하지 않는다. `--rule`로 입력·버튼 상태나 유일한 구조 정보를 전달하지 않는다. 대비는 실제 글자/배경 쌍으로 검수한다.

### 4.2 서체와 조판

Pretendard Variable 한 가족을 자체 호스팅한다. fallback은 Apple SD Gothic Neo / Malgun Gothic / system-ui / sans-serif. 코드·문서번호·REV에만 시스템 monospace를 사용하며 한국어는 Pretendard로 fallback한다.

| 역할 | 크기 | 행간·굵기 |
|---|---|---|
| 홈 대표 문장 | 데스크톱 44~88px, 모바일 44~65px | 1.12~1.15 / 850 |
| 섹션 제목 | 28~48px | 1.2 / 760 |
| 대표 기록 제목 | 25~38px, 모바일 30px | 1.27 / 750 안팎 |
| 최근 기록 제목 | 20~21px | 1.4 / 650 이상 |
| 아티클 본문 | 17px | 1.85 / 400 |
| 보조 정보 | 12~14px | 1.5 이상 |

큰 제목은 한글 어절을 유지하고 의도한 문장 단위로 나눈다. 본문은 `word-break: keep-all; overflow-wrap: anywhere`, 최대 38em. 긴 URL·식별자는 별도 줄바꿈을 허용한다. `text-wrap: balance`는 향상 요소이며 지원하지 않아도 문장이 읽혀야 한다.

시안은 외부 연결 없이 열 수 있도록 Pretendard의 **해당 화면 글리프를 포함한 WOFF2 subset 91,468 bytes**를 HTML 안에 넣었다. 원본 출처와 SIL OFL 1.1 전문을 파일에 포함했다. 운영 빌드는 글별 필요한 한글 범위를 갖는 자체 호스팅 파일로 분리하며, 새 글이 추가될 때 subset도 갱신한다. fallback 메트릭과 실제 CLS는 구현 단계에서 측정한다.

### 4.3 배치와 형태

- 컨테이너 최대 1400px, 좌우 여백 20~60px. 섹션 간격 데스크톱 80px, 모바일 52px를 기본으로 한다.
- 1100px 이상: 히어로·대표 기록·서비스를 2단, 기록 갤러리 4열로 배치한다.
- 761~1100px: 갤러리는 2열, 대표 기록 도판 비율을 조정한다.
- 760px 이하: 히어로·대표 기록·서비스를 1단으로 배치하고 갤러리는 썸네일+제목의 세로 목록으로 바꾼다.
- 이미지·썸네일은 데스크톱 22px, 모바일 16px 모서리. 대표 도판·펼친 글·문의 구역은 20~26px. 버튼·분류 선택·테마 select는 pill 형태다. 그림자·그라데이션은 추가하지 않는다.
- 히어로 도판 네 개는 같은 시작 높이로 놓고 회전과 외부 치수선을 없앤다. 그림 밑 캡션은 프레임 밖의 평문이다.
- 헤더·섹션·대표 기록·서비스·기술 목록·기록 원칙·접힌 글·문서 정보에는 외곽 테두리와 반복 구분선이 없다. 제목·열 정렬·여백으로 관계를 드러낸다.
- 펼친 글과 문의 구역은 약한 배경 면으로 구분한다. 문서 정보에는 별도 배경 상자나 칸막이를 추가하지 않는다.
- 기본 UI의 선은 개정 표 머리 아래 가로선에 한정한다. 키보드 포커스와 forced-colors에서는 식별에 필요한 윤곽선을 유지한다.

| 헤더 | 워드마크, 기록·서비스·기록 원칙, 테마·모션 | 관심 영역으로 이동 |
| 히어로 | 대표 문장, 짧은 소개, 2×2 도판 | 대표 기록을 읽거나 네 주제를 선택 |
| 대표 기록 | 큰 경계 도판, 제목, 판단 요약, 개정 라벨 | 샘플 아티클 펼치기 |
| 최근 기록 | 네 가지 주제의 커버와 질문, 분류 필터 | 제목을 비교하고 읽기 |
| 서비스 | DJC / WithBuddy 비대칭 패널, 관련 기록 | 공개 서비스 또는 사례로 이동 |
| 기술과 역할 | 포털 기술과 사례에서 다루는 기술 구분 | 운영 기술을 맥락과 함께 이해 |

| 주제별 탐색 | native details 네 개 | 해당 문제의 글 목록 열기 |
| 설계 노트 | 네 개의 native details 샘플 글 | 표제란·본문·개정 표현 확인 |
| 구독·문의 | 실제 연결 전 동선 설명 | 공개용 구현에서 유효한 목적지 연결 |

### 5.1 히어로와 도판

문장은 “만들고,” / “운영하고,” / “근거를 남깁니다.”의 세 행. 두 번째 행을 Cobalt로 강조하고 장식 밑줄은 없앤다. 텍스트와 도판이 겹치지 않는 두 영역을 확보한다.

네 도판은 **배포 경계 / 캐시의 경계 / 답변의 근거 / 개정이 남는 기록**이다. 제목과 캡션을 상시 노출하고 각각 해당 글로 연결한다. 정밀한 의미가 필요한 도식은 SVG로 작성한다. 외곽 프레임·눈금은 생략하고 노드·연결·텍스트만 남긴다. 한 도판을 마우스에 올리면 3px 이동하며, 키보드 포커스는 별도 윤곽선으로 보인다.

### 5.2 대표 기록과 갤러리

대표 기록의 질문은 “페이지는 정적으로, 운영은 가볍게.”다. 왼쪽 그림은 itsdev.kr 콘텐츠 생성·배포 경계를 표현한다. 오른쪽에는 제목 아래 문제·선택·검증을 세 행으로 적고 실행 전 상태를 명시한다. 세 행 사이 선과 대표 기록을 감싸던 바깥 박스는 없앤다. 확인 결과가 없는 그림에 성공 체크나 성능 수치를 넣지 않는다.

최근 기록은 커버의 높이 차이로 리듬을 만든다. 제목·질문·분류가 실제 탐색 정보이며, REV·검증 라벨은 값이 있을 때만 표시한다. 시안의 필터는 JS 향상 기능이다. JS가 없으면 모든 기록이 보이고 글을 읽을 수 있다. 운영 사이트의 분류는 정적 URL 링크로 제공한다.

### 5.3 서비스와 기술

DJC 패널은 조금 더 넓게, WithBuddy는 데스크톱에서 60px 아래로 시작한다. 모바일에서는 시작 높이를 맞춘다. 두 서비스의 화면·구성을 개편하지 않고 소개와 관련 기록만 다룬다.

실제 캡처가 없으면 제품 흐름을 설명하는 개념 도판을 사용한다. 서비스 제목 위 굵은 선과 흐름 단계별 테두리는 없애고 소개·그림·링크를 여백으로 구분한다. 확인한 화면은 캡처 날짜·목적지를 함께 관리한다. 기술 목록은 박스 없이 정적 텍스트로 보여준다. Astro + Workers가 포털의 조합이며 Spring Boot / Redis / RAG / SSE 등은 서비스 기록의 소재다.

## 6. 아티클의 시그니처

### 6.1 표제란

표제란은 문서번호·분류/유형·환경·검증 상태·개정으로 구성하는 `<dl>`이다. 표제란의 의미를 유지하되 외곽선·칸별 선·별도 상자는 제거하고 라벨과 값의 간격으로 표현한다. 데이터가 없으면 해당 칸을 숨긴다. 빈 칸이나 N/A를 만들지 않는다. 모바일에서는 제목 직후, 본문 전에 놓는다. 시안에서는 샘플 글 제목을 연 뒤 표제란과 본문을 확인할 수 있다.

문서번호는 **불변 `documentId`**다. slug의 해시나 발행연도를 매 빌드마다 조합하지 않는다. 최초 작성 시 부여하고 중복 여부를 빌드에서 검증한다. URL·제목·분류를 바꿔도 번호를 유지한다.

| 필드 | 용도 | 규칙 |
|---|---|---|
| `documentId` | 문서 식별 | 필수, 불변, 저장소 전체에서 유일 |
| `category`, `articleType` | 분류 / 유형 | 정의한 목록에서 선택 |
| `environment` | 적용 환경 | optional 문자열 배열, 실제 조건만 |
| `evidenceStatus` | 검증 상태 | planned / partial / verified |
| `verifiedAt` | 확인 시점 | 실제 확인 날짜가 있을 때만 |
| `revisions[]` | 개정 이력 | `rev`, `date`, `summary`를 명시적으로 기록 |
| `cover`, `coverAlt`, `coverFocus` | 글 커버 | cover가 있으면 설명과 위치를 함께 검수 |

`verified`는 실제 실행 근거가 있을 때만 사용한다. 일부 검증·실행 전은 텍스트와 Redline으로 함께 표시한다. `changeSummary`의 글자 수·항목 수로 REV를 계산하지 않는다.

### 6.2 본문과 개정

글의 기본 흐름은 문제 → 환경/대안 → 선택 → 구현 → 검증 → 한계 → 다음 판단. 짧은 글에 모든 제목을 강제하지 않는다. 제목 아래 핵심 질문을 쓰고, 숫자를 제시할 때는 조건·단위·기간을 함께 적는다.

개정 표는 REV·날짜·변경 이유의 3열이며 최신 REV만 Redline으로 표시한다. 행마다 테두리를 그리지 않고 머리 아래 선 하나와 정렬로 읽는다. 본문은 현재의 정확한 설명으로 갱신하고, 과거 판단과 수정 이유는 이력에 남긴다. 위험하거나 잘못된 이전 설명을 본문에서 유효한 지시처럼 유지하지 않는다.

운영 사이트의 장문 아티클은 목차·표제란·38em 본문·근거 주석을 제공한다. 좁은 화면의 각주는 해당 문단 뒤에 놓는다. 복잡한 코드·표는 해당 블록만 가로 스크롤할 수 있고 페이지 전체는 넘치지 않아야 한다. 본문에 진입·퇴장 모션을 넣지 않는다.

시안은 본문 폭·선 없는 문서 정보·개정 표·관련 이동을 구현했다. 독립 아티클 라우트, 목차, 복사 버튼, Shiki 코드 테마, 실제 근거 주석은 운영 사이트 구현 시 추가할 항목이다.

## 7. 모션과 상호작용

| 대상 | 동작 | 조건 |
|---|---|---|
| 데스크톱 히어로 | 10px 상승, 0.7초, 도판 0.12초 시차 | JS 향상 활성, 탭 세션 첫 방문 |
| 워드마크 치수선 | stroke draw, 0.8초 | 같은 조건, 반복 없음 |
| 첫 화면 아래 패널 | IntersectionObserver 진입 후 10px 상승, 0.55초 | 대상당 1회 |
| 도판 hover | 3~4px 이동, 0.25초 | reduced-motion에서는 없음 |
| 테마 | 시스템 / 밝게 / 어둡게 선택 | localStorage 실패해도 조작 가능 |
| 분류 | 필터 버튼, 선택 상태와 결과 수 갱신 | `aria-pressed`, 결과는 status로 전달 |
| 주제·샘플 글 | native details 열기/닫기 | JS 없이도 동작 |

콘텐츠의 기본 상태는 항상 보임이다. `opacity:0`, blur, clip으로 읽기 내용을 숨긴 뒤 복구하는 방식을 쓰지 않는다. JS·IntersectionObserver·저장소가 없거나 실패해도 본문을 읽을 수 있다. 스크롤 하이재킹·패럴랙스·무한 ticker·커서 추적은 없다.

상단에 “모션 끄기 / 켜기” 버튼을 둔다. OS `prefers-reduced-motion: reduce`가 우선하며 이때 애니메이션·전환을 모두 끄고 버튼에는 OS 설정 상태를 표시한다. CSS와 JS 양쪽에서 처리한다. 모션을 꺼도 색·정보·레이아웃은 유지된다.

현재 시안에는 별도 페이지 전환 효과가 없다. cross-document View Transition은 운영 구현에서 지원 여부와 읽기 경험을 확인한 뒤 선택하며 핵심 요구사항으로 삼지 않는다.

## 8. 접근성과 실패 상태

- `lang="ko"`, 하나의 H1, 본문 바로가기, 의미 있는 heading 구조를 유지한다.
- 링크·버튼·select·summary는 키보드로 조작 가능하고 포커스에 3px 윤곽선을 표시한다.
- 일반 컨트롤은 최소 높이 44px. 도판 캡션은 hover나 터치 동작 없이 보인다.
- 외부 링크는 목적지 도메인과 ↗를 표시한다. 새 창 링크에는 `noopener noreferrer`를 사용한다.
- SVG는 title/desc와 고유한 ID를 갖는다. 복잡한 도판의 의미는 인접한 글에도 설명한다.
- JS off에서 모든 기록·핵심 링크·native details가 유지된다. JS 전용 필터/테마/모션 컨트롤만 숨기고 OS 테마를 따른다.
- forced-colors에서는 이미지와 버튼·선택 상태에 식별 가능한 윤곽선을 추가한다. 문서 정보는 라벨과 값으로 읽을 수 있다. 색만으로 상태를 전달하지 않는다.
- 모바일의 기록은 세로로 읽는다. 필수 정보를 가로 슬라이더 안에 가두지 않는다.
- 이미지는 비율과 폭/높이를 사전 예약하고, 실패 시 설명을 남긴다. 빈 기록·미확정 링크·미측정 상태에 가짜 값을 채우지 않는다.

## 9. 이미지·성능·구현 인계

운영 커버는 SVG 또는 자체 제작 이미지로 구성한다. AVIF/WebP 변환과 반응형 `srcset/sizes`는 Astro 빌드 단계에서 처리한다. 아래 이미지는 lazy load하고 첫 화면의 우선순위는 실제 LCP 관측 후 정한다. “텍스트가 반드시 LCP”라고 가정하지 않는다.

| 항목 | 운영 예산 / 원칙 | 이번 시안 |
|---|---|---|
| CSS | gzip ≤18KB, 폰트 제외 | 약 5KB, 인라인 |
| 자체 JS | gzip ≤8KB, 테마 포함 | 약 1KB, 외부 라이브러리 없음 |
| 폰트 | 첫 화면 전송 ≤120KB | WOFF2 subset 91,468 bytes |
| 첫 화면 이미지 | 압축 전송 합계 ≤300KB | 인라인 SVG, 별도 이미지 요청 없음 |
| 핵심 읽기 | JS 없이 가능 | 정적 HTML + native details |
| 배포 | Astro build → Workers Static Assets → itsdev.kr | 실제 배포 실행 전 |

시안의 단일 HTML에는 오프라인 표시를 위한 폰트와 도판이 들어간다. 운영 빌드는 캐시 가능한 CSS·폰트·자산으로 나누고 파일명에 해시를 붙인다. HTML 용량과 자산 전송 예산을 혼동하지 않는다. Lighthouse/실사용 LCP·INP·CLS는 구현·배포 후 별도로 측정한다.

컴포넌트 인계: SiteHeader / Hero / DrawingAtlas / LeadStory / DecisionStrip / RecordGallery / ServiceFeature / StackContext / ReadingMethod / TopicDetails / TitleBlock / RevisionTable / SiteFooter. 시안용 SampleNote와 연락 안내는 공개용 라우트·유효 링크로 교체한다.

OG는 1200×630 제목+분류+문서번호+실제 REV 조합으로 빌드 생성한다. RSS는 실제 공개 콘텐츠로 생성한다. 초기 홈·목록 광고는 없고, 광고 적용 여부와 아티클 배치는 기존 PRD의 별도 조건을 따른다. 시안에 광고 자리나 승인 상태를 만들지 않는다.

## 10. 검수 결과와 남은 조건

2026-10-07 로컬 Chromium 133 headless에서 1440·768·390·320px 화면, 밝은/어두운 테마, JS off, 분류 필터, 샘플 글 이동, 테마 전환, 모션 정지를 확인했다. 페이지 가로 넘침·누락된 내부 앵커·브라우저 JS 오류가 없었다. 대표 글과 모바일·다크 화면을 캡처해 시각 검수했다. 이번 v8에서는 프레임 제거와 모서리 변경 후 같은 범위의 조작·reflow를 다시 확인했다.

이 결과는 시안의 검수다. Safari/Firefox·실기기·VoiceOver/NVDA·200% 확대·인쇄·실제 자산 로딩·프로덕션 성능은 완료로 표시하지 않는다. 출시 전에는 긴 실제 제목·코드·표·URL, 이미지 오류, 개정 없는 글과 여러 번 개정한 글, 키보드 전체 경로도 확인한다.

반려 조건: 콘텐츠마다 테두리 상자 추가, 섹션마다 구분선 반복, 각진 UI 복귀, 샘플을 실적으로 표시, 기존 서비스의 미출시 추정, 서브도메인 재설계 포함, 텍스트와 타일 겹침, 핵심 내용의 JS 의존, 대비 미달, 페이지 가로 넘침, 의미 없는 반복 모션, 확인되지 않은 연락처·목적지, 폰트 예산 초과 상태로 공개.

이번 결과물은 **디자인과 상호작용이 구현된 검토용 시안**이다. 실제 콘텐츠 반영·브랜드 승인·Workers 배포 완료를 뜻하지 않는다.
